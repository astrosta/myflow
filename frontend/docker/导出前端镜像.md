# 前端镜像：Windows 构建，Ubuntu 运行

本次产物：

- 镜像名：`myflow-frontend:local`
- 导出文件：`d:\python\myflow\myflow-frontend.tar`（约 72MB；`docker images` 显示约 300MB）

这个包只有前端。`docker-compose.yml` 里的 `myflow-gateway:local` 不会一起打出来，Ubuntu 上要先有网关镜像，`frontend` 才能起来。

## 1. Windows：构建

先确认 Docker Desktop 已启动（`docker version` 里能看到 Server）。

```powershell
cd d:\python\myflow\frontend\docker
docker compose build frontend
```

产物标签是 `myflow-frontend:local`。

构建依赖 `frontend/docker/Dockerfile`：

- `pnpm install` 加长了重试和超时，避免连 `registry.npmjs.org` 中途断开。
- 构建阶段直接执行 `./node_modules/.bin/next build`（builder 阶段没有 `pnpm` 命令）。

## 2. Windows：导出

```powershell
docker save myflow-frontend:local -o d:\python\myflow\myflow-frontend.tar
```

把下面两个东西拷到 Ubuntu：

- `myflow-frontend.tar`
- 仓库里的 `frontend/docker/docker-compose.yml`（启动时要用）

## 3. Ubuntu：导入并启动

```bash
docker load -i myflow-frontend.tar

# 确认镜像在
docker images | grep myflow-frontend

cd /path/to/myflow/frontend/docker
docker compose up -d
```

默认只监听本机 `127.0.0.1:2026`。要对局域网开放：

```bash
BIND_HOST=0.0.0.0 docker compose up -d
```

浏览器访问 `http://127.0.0.1:2026`。对外绑定时用机器 IP。

不要加 `--build`。`--build` 会在 Ubuntu 上重新构建，而不是使用刚导入的镜像。

## 4. 常用命令

```bash
docker compose ps
docker compose logs -f frontend
docker compose down
```
