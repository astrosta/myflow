# myflow-evals 使用指南

面向日常操作：如何配环境、建数据集、跑评测、读结果。设计细节与指标定义见 [README.md](./README.md)。

## 它做什么

`myflow-evals` 是独立黑盒评测包：用固定测试账号登录 Gateway，按 Langfuse 数据集里的样本逐条跑 Agent，读取运行事件账本，用**规则评测器**打分；配置评判模型后还会用 DeepEval/LLM 指标补充回答质量分数，最后把分数写回 Langfuse 实验。

要点：

- 只通过 HTTP 访问 Gateway 与 Langfuse，不导入 `backend` / `agentkit`
- 规则指标（工具命中、路由、检索召回、引用等）始终运行，是主要门禁
- LLM 指标（Faithfulness、answer_correctness、skill_adherence、refusal_ok 等）需要评判模型；不配置时只跑规则指标
- DeepEval 是可选 `llm` extra；未安装时 `auto` 引擎用内置 prompt 引擎，两者共用同一个 OpenAI 兼容接口
- 被测 Agent 本身仍会调模型；那是 Gateway 侧的模型配置，与评测包无关

## 一次配好

### 1. 安装

在仓库根目录：

```bash
uv sync --project evals
uv run --project evals myflow-evals --help

# 需要 DeepEval RAG 指标时再装可选 extra
uv sync --project evals --extra llm
```

### 2. 准备机密

复制模板并填入真实值（不要提交 `.env`；仓库里的模板是 `env.template`）：

```bash
cp evals/env.template evals/.env
```

| 变量 | 必填场景 | 说明 |
| --- | --- | --- |
| `AGENT_API` | `build` / `run` / `ingest` | Gateway 地址，如 `http://127.0.0.1:8001/api` |
| `AGENT_USERS` | 同上（或改用 `--accounts-file`） | JSON：`{"标签":{"username":"...","password":"..."}}` |
| `USER_ID_SALT` | `build` / `run` / `ingest` | 必须与 Agent 追踪配置 `user_id_salt` **完全一致** |
| `LANGFUSE_HOST` | `run`、真实 `build`、`ingest` | 如 `https://cloud.langfuse.com` 或自建地址 |
| `LANGFUSE_PUBLIC_KEY` | 同上 | Langfuse 公钥 |
| `LANGFUSE_SECRET_KEY` | 同上 | Langfuse 私钥 |
| `EVAL_JUDGE_BASE_URL` / `EVAL_JUDGE_API_KEY` / `EVAL_JUDGE_MODEL` | 可选；`build --llm-synthesis` 与 LLM 指标必填 | OpenAI 兼容评判模型；三者都填才启用。`EVAL_JUDGE_API_KEY` 缺省时回退 `OPENAI_API_KEY` |
| `EVAL_JUDGE_TEMPERATURE` 等 | 可选 | 默认温度 `0`、超时 `60s`、`max_tokens` `2048`；温度须为非负浮点数 |
| `EVAL_METRIC_ENGINE` | 文档预留 | 文档写了环境变量，当前请用 `run --metric-engine`（`auto` / `prompt` / `deepeval`） |
| `EVAL_LLM_SAMPLE` / `EVAL_LLM_SEED` | 文档预留 | 文档写了环境变量；比例请用 `run --llm-sample`，种子默认 `agent-eval` |

也可用命令行传入：

```bash
uv run --project evals myflow-evals build \
  --env-file evals/.env \
  --accounts-file /path/to/accounts.json \
  --dataset agent-eval/explore \
  --dry-run
```

真实环境变量优先于 `--env-file`，CI secrets 不会被仓库里的文件覆盖。

### 3. Gateway 前置条件

被测 Gateway 必须满足，否则分数没有设计上的含义：

- `auth.enabled=true`
- 追踪 `user_id_mode=hashed`，盐与 `USER_ID_SALT` 相同
- `subagent_enabled=true`，且 `skill-finder`、`knowledge-researcher` 可用
- `skills.usage.prompt_top_k=0`（私有 Skill 不进静态提示索引）
- `run_events.backend=db` 或 `jsonl`（不能是 `memory`）
- 测试账号已完成首次改密（`needs_setup=false`）

评测账号下应已有可用的 MCP 工具（Gateway 投影里 `callable`+`enabled`）、私有 Skills、知识库文档——`build` 只采样这些生效来源。

## 日常流程

推荐顺序：先 dry-run 看清来源 → 写入数据集 → dry-run 看清实验规模 → 正式跑分。

### 第一步：试构建（不写 Langfuse）

```bash
uv run --project evals myflow-evals build \
  --env-file evals/.env \
  --dataset agent-eval/explore \
  --limit 20 \
  --dry-run
```

会登录账号、读取 MCP / Skills / 知识库，打印每种来源能生成多少草稿、按类别/来源/难度的分布、质检问题与警告，以及数据集 fingerprint。  
`--dry-run` 的 `build` **不需要** Langfuse 密钥。默认是扩展构建：每个工具/Skill 生成 2 条，再补 missing_params、similar_tools、multi_tool、kb_multi_hop、kb_unanswerable、no_tool 等类别；加 `--no-expand` 可回到阶段 1 的一来源一草稿。

### 第二步：写入数据集

回归集（可评分，不含追踪回放）：

```bash
uv run --project evals myflow-evals build \
  --env-file evals/.env \
  --dataset agent-eval/regression/v1 \
  --limit 100
```

探索集（可含失败/低分追踪，**不要**拿去跑回归门禁）：

```bash
uv run --project evals myflow-evals build \
  --env-file evals/.env \
  --dataset agent-eval/explore \
  --include-traces \
  --limit 100
```

说明：

- 默认扩展构建；写入前会按“账户 + 规范化 query”去重，并检查 hashed user_id、query、期望字段、重复 ID、重复 query、工具名安全性、期望工具/期望 Skill 是否属于该账号、KB 文档 ID 是否属于该账号、KB 参考答案是否为空。
- 加 `--strict`：质检发现问题时以退出码 2 终止，**不写入任何条目**。冻结回归集前建议先 `--dry-run --strict`。
- 同名数据集再次 `build` 会 upsert 条目，**不会删除**已消失来源的旧条目；新版本请换名（如 `agent-eval/regression/v2`）
- `--seed N` 可固定知识库分块抽样；条目 ID 与抽号无关
- 默认不加 `--include-traces`：追踪回放没有期望，跑 `run` 会因 `unscored` 失败
- 记下输出里的 `fingerprint`；实验 metadata 的 `dataset_fingerprint` 应与它一致

### 用 LLM 增强评测集（`--llm-synthesis`）

默认 `build` **全程确定性**：不调评判模型、不产生模型费用，相同账号数据 + `--seed` 可复现。  
`--llm-synthesis` 是可选增强：在确定性草稿之上，用 `EVAL_JUDGE_*` 配置的 OpenAI 兼容模型做两件事：

1. **改写 query**：把模板问法改成更自然的用户请求  
2. **提炼 `skill_rules`**：从私有 Skill 的描述生成规则列表（Gateway 只暴露元数据，没有 SKILL.md 正文）

它**不会**：

- 凭空生成新类别样本（如设计表里的 `kb_conflict` / `hybrid`）
- 改变来源采样与期望结构（工具名、`expected_doc_ids` 等仍由确定性路径决定）
- 在评判失败时中止构建：超时、非 JSON、数量不符时回退确定性文本，并打印不含 prompt 内容的 `warning:`

#### 前置条件

`.env` 中配齐评判模型（与跑 LLM 指标共用同一套）：

```bash
EVAL_JUDGE_BASE_URL=https://api.deepseek.com/v1
EVAL_JUDGE_API_KEY=sk-...
EVAL_JUDGE_MODEL=deepseek-chat
# 可选：EVAL_JUDGE_TEMPERATURE=0
```

未配置时加 `--llm-synthesis` 会直接退出码 2。不需要安装 DeepEval extra；改写走的是评判 HTTP 客户端，不是 DeepEval。

#### 推荐操作

先小规模 dry-run，确认警告可接受、分布正常：

```bash
uv run --project evals myflow-evals build \
  --env-file evals/.env \
  --dataset agent-eval/explore \
  --llm-synthesis \
  --limit 5 \
  --dry-run
```

再写入回归集（建议仍先限制规模，人工抽检问法后再全量）：

```bash
uv run --project evals myflow-evals build \
  --env-file evals/.env \
  --dataset agent-eval/regression/v1 \
  --llm-synthesis \
  --limit 20 \
  --strict
```

Windows PowerShell：

```powershell
uv run --project evals myflow-evals build `
  --env-file evals/.env `
  --dataset agent-eval/regression/v1 `
  --llm-synthesis `
  --limit 20 `
  --strict
```

#### 成本与质检

- 大约**每条草稿一次**评判调用，费用随 `--limit` 与账号下来源数增长；先小 `--limit` 再放开。
- 改写结果仍走同一套去重与结构质检；`--strict` 时质检问题仍会整批拒绝写入。
- 冻结前抽检若干条：问法是否自然、是否仍指向正确工具/Skill/文档、Skill 规则是否过宽或过窄。
- 需要可复现、可对比的基线时，用**不带** `--llm-synthesis` 的确定性构建；LLM 增强集建议用新数据集名（如 `.../v1-llm`）单独冻结。

### 第三步：试跑实验（不启 Agent）

```bash
uv run --project evals myflow-evals run \
  --env-file evals/.env \
  --dataset agent-eval/regression/v1 \
  --mode ci \
  --dry-run
```

只读 Langfuse 数据集并打印将选多少条目；不登录 Gateway，不写分数。

### 第四步：正式评测

CI 子集（约 30 条分层样本）：

```bash
uv run --project evals myflow-evals run \
  --env-file evals/.env \
  --dataset agent-eval/regression/v1 \
  --mode ci \
  --run-name "local-$(date +%Y%m%d-%H%M)" \
  --max-concurrency 2
```

全量（建议装 DeepEval extra：`uv run --project evals --extra llm myflow-evals run ...`；配置评判模型后 LLM 指标成为硬门禁）：

```bash
uv run --project evals myflow-evals run \
  --env-file evals/.env \
  --dataset agent-eval/regression/v1 \
  --mode full \
  --run-name "full-$(date +%Y%m%d-%H%M)" \
  --max-concurrency 2
```

可用标志与行为：

- `--metric-engine auto|prompt|deepeval`：默认 `auto`；显式指定引擎但没有评判模型时退出码 2。
- `--llm-sample 0.2`：适用条目中被 LLM 指标评分的比例；`ci` 默认 0.2，`full` 默认 1.0。
- 没有配置 `EVAL_JUDGE_*` 时，`run` 会打印一行警告并只跑规则指标；评判失败只让该 metric 缺失，不影响规则门禁，结果会显示 `llm metric errors:`。

Windows PowerShell 可用：

```powershell
uv run --project evals myflow-evals run `
  --env-file evals/.env `
  --dataset agent-eval/regression/v1 `
  --mode ci `
  --run-name ("local-" + (Get-Date -Format "yyyyMMdd-HHmm"))
```

### 可选：浏览失败追踪

```bash
uv run --project evals myflow-evals ingest \
  --env-file evals/.env \
  --dataset agent-eval/explore \
  --limit 50
```

默认只打印候选追踪，不写入数据集。要把它们放进探索集：

```bash
uv run --project evals myflow-evals ingest \
  --env-file evals/.env \
  --dataset agent-eval/explore \
  --limit 50 \
  --write
```

写入的条目是 `category=trace_replay`、`expected_output={}`、`review_status=pending`，只能进探索集；不要放进回归门禁。加 `--dry-run` 可预览而不写。

## 怎么读结果

成功时 stdout 类似：

```text
dataset: agent-eval/regression/v1
run: ci-20261110 (mode ci)
items: 30 of 30 returned
scorable items: 30
retrieval_recall@5: 0.980 min 0.95 samples=30 PASS
tool_hit: 0.933 min 0.90 samples=30 PASS
...
result: PASS
experiment: https://...
```

| 现象 | 含义 |
| --- | --- |
| `PASS` / `FAIL` | 带阈值指标的平均值是否达标 |
| `samples=0` / `insufficient` | 没有样本产出该指标分数（不等于测过且通过） |
| `citation_valid` 任一为 0.0 | 整次运行失败 |
| `forbidden_violation` 任一为 1.0 | 整次运行失败 |
| `unscored` | 条目完成了但没有任何评测（常见于追踪回放） |
| `invalid_routing` | 该走 skill/kb 子代理却直接答了 |
| `llm metric errors: ...` | 评判调用失败；规则门禁仍然有效，检查评判端点/密钥/超时 |
| LLM 指标 `insufficient` | 适用样本少于 20 条（或未配置评判模型），不是测过且通过 |

退出码：

| 码 | 含义 |
| --- | --- |
| `0` | 完成（含 dry-run 成功） |
| `1` | 实验失败（门禁、缺条目、运行非 success、unscored 等） |
| `2` | 配置/依赖不可用（缺密钥、空数据集、Gateway/Langfuse 不可达等） |

详细指标表与失败分类见 [README.md](./README.md)「结果：门禁、分数与不完整实验」。

## 常见问题

**要不要配 OpenAI / DeepEval API key？**  
只跑规则指标、且不做 LLM 增强构建时不需要：Gateway + 测试账号 +（除 build dry-run 外）Langfuse 就够。需要 `build --llm-synthesis`，或 Faithfulness、answer_correctness、skill_adherence、refusal_ok 等 LLM 指标时，配置 `EVAL_JUDGE_BASE_URL` / `EVAL_JUDGE_API_KEY` / `EVAL_JUDGE_MODEL`；要用 DeepEval 引擎再 `uv sync --project evals --extra llm`。

**`--llm-synthesis` 和确定性构建差在哪？**  
确定性构建只根据 MCP / Skill / 知识库模板生成问法；`--llm-synthesis` 在此基础上改写问法并提炼 Skill 规则，不新增 `kb_conflict` / `hybrid` 等类别。失败会回退模板文本，构建不会因此中断。

**`build --dry-run` 为什么还要登录？**  
来源按账号隔离，不登录就看不到真实 MCP/Skill/知识库数量。它只是不写 Langfuse。

**工具草稿一直是 0？**  
检查 Gateway 是否支持 `GET /api/mcp-servers/{id}/tools?include_schema=true`，以及工具是否同时 `callable` 且 `enabled`、带对象形式 `input_schema`。看构建报告里的 `warning:` 行。

**构建报 `duplicate normalized query` / `no declared expectation`？**  
这是质检问题。先在 `--dry-run --strict` 下看具体条目；确认是模板重复还是坏来源。`--strict` 会阻止写入，删掉问题来源或换 `--no-expand` 再试。

**为什么扩展构建只有少数类别？**  
类别取决于真实来源：没有必填参数就没有 `missing_params`，没有相近描述就没有 `similar_tools`/`similar_skills`，没有相关分块就没有 `kb_multi_hop`，没有破坏性工具就没有 `injection`。构建报告里的 `empty category` 是提示，不是失败。

**改了 `USER_ID_SALT`？**  
所有哈希用户 ID 都会变，必须重建数据集，旧条目无法对上账号。

**CI 会不会自动 build？**  
不会。工作流把数据集当冻结输入，只 `run`。数据集变更需人工 `build` 后冻结新版本名。

## 命令速查

| 命令 | 作用 | 写 Langfuse？ | 调 Agent？ |
| --- | --- | --- | --- |
| `build --dry-run` | 统计可生成草稿 | 否 | 否（只读账号数据） |
| `build` | 确定性扩展合成、去重、质检并 upsert | 是 | 否 |
| `build --strict` | 质检失败则不写并退出 2 | 否（失败时） | 否 |
| `build --llm-synthesis` | 确定性草稿 + 评判模型改写问法/提炼 Skill 规则 | 是 | 否（只调评判模型） |
| `run --dry-run` | 打印将跑多少条 | 否（只读数据集） | 否 |
| `run` | 执行样本并打分 | 是（实验分数） | 是 |
| `ingest` | 打印失败/低分追踪 | 否 | 否 |
| `ingest --write` | 把候选追踪写入探索集（pending） | 是 | 否 |

共享标志：`--dataset`（必填）、`--limit`、`--env-file`、`--accounts-file`；`build` 另有 `--seed`、`--include-traces`、`--no-expand`、`--strict`、`--llm-synthesis`；`run` 另有 `--mode`、`--run-name`、`--max-concurrency`、`--metric-engine`、`--llm-sample`；`ingest` 另有 `--write`。
